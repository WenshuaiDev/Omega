# 青藏高原野外观测体系 32:9 展厅可视化大屏开发规格

规格编号：POV-01 · 版本：1.0 · 编制日期：2026-09-25

交付类型：完整、可构建、可部署、可持续运行的纯前端可视化工程。

数据方式：浏览器内动态模拟业务数据，公开地理样例资源，自制或可再分发的工程样例模型。运行时无需业务后端、数据库、设备接入服务、付费地图账号或用户补充资料。

验收优先级：视觉与动效优先，同时满足完整交互、地理表达、数据一致性和连续运行要求。用户已明确选择“更侧重视觉与动效验收”。

## Problem Statement

展厅需要一套面向领导视察和讲解的 32:9 超宽屏，完整展示青藏高原野外观测体系的数字化监测建设。观众应先理解体系的地理全貌及“一站、两廊、三场”，再沿真实地理环境进入交通基础设施、监测点、设备和观测数据。

体系覆盖路基路面、桥梁、涵洞、气象四类专业。路基与路面需要不同的模型和指标，因此界面包含总览、路基、路面、桥梁、涵洞、气象六个完整场景。当前内容边界不包含告警、处置、风险研判和科研。

用户没有测绘文件、设备台账、模型或监测数据，也不负责补齐这些资料。开发应主动完成公开地理样例资源准备、模型制作、样例对象编排和动态数据模拟。样例数据是正式交付工程的运行方式，不能据此降低界面完成度、资产质量、交互覆盖或运行可靠性。

八张旧版效果图只提供监测业务内容依据。其中的地图布局、装饰框、导航、面板比例、曲线形状、统计数字、科研叙事和示意地理位置均不是设计或事实依据。新界面应以中交第一公路勘察设计研究院有限公司的企业背景和中交蓝色体系建立独立视觉语言，形成真实地貌、工程模型与科技动效相结合的展厅效果。

## Solution

建设单一前端应用，以真实地理底座承载模拟观测体系：CesiumJS 展示公开卫星影像、真实高程、国道走向与区域范围；Three.js 展示精细工程样例模型和设备挂点；React 负责信息界面；ECharts 展示由统一模拟时钟驱动的时序和深度剖面数据。浏览器内的统一模拟运行时同时驱动地图标注、模型测点、数值卡片、曲线和统计。

默认打开完整总览。画面突出一座野外观测站、格尔木—那曲和共和—玉树两条国道走廊，以及气候环境、结构材料、实体工程三种观测场的示例范围。范围、设施和设备均有图层与选择联动；设施可从地理场景进入工程模型，并继续选择具体构件、孔位、测点和指标。自动巡航和人工讲解使用相同的交互能力与场景状态。

“准确地理”在本工程中的含义是：地形、影像、地名和道路来自有来源记录的公开空间数据，并正确配准；项目站点、三场边界、设施布设和业务数值采用确定性的样例配置。后者不能宣称是中交一公院实际建设清单或测绘成果。主界面以统一、简洁的“模拟观测数据”标识说明业务数据性质；查看资料来源时可进一步区分地理实景、工程样例模型和模拟布设。

完整交付包括六个场景、两条可讲解走廊、三类范围图层、可交互模型、全部旧图相关指标、动态模拟引擎、离线静态资产包、讲解控制、错误恢复、构建与运行说明、视觉截图、动效录屏及验收记录。

## User Stories

1. As an 展厅观众, I want 一进入大屏就看见青藏高原的三维地貌, so that 我能建立对观测体系所在地理环境的直观认识。
2. As an 展厅观众, I want 同时辨认一站、两廊、三场及其名称, so that 我能理解体系的总体组成。
3. As an 展厅观众, I want 看见格尔木—那曲与共和—玉树走廊的真实道路走向, so that 我能理解观测设施的沿线分布。
4. As an 展厅观众, I want 看见三种观测场的地表范围与图例, so that 我不会将三场误解成三个孤立测点。
5. As an 展厅观众, I want 看见路基路面、桥梁、涵洞与气象四类专业, so that 我能理解体系观测哪些对象。
6. As an 展厅观众, I want 看见中交一公院的企业名称和统一蓝白品牌气质, so that 我能识别展示主体。
7. As an 展厅观众, I want 在远距离看清主要标题、设施名称和核心数值, so that 我不必走近屏幕才能理解内容。
8. As an 展厅观众, I want 通过平滑镜头和空间高亮跟随讲解, so that 我能知道每次展示转向何处。
9. As an 讲解人员, I want 一键启动完整巡航, so that 我能按预设节奏展示全体系。
10. As an 讲解人员, I want 暂停、继续、跳到上一段或下一段, so that 我能配合现场讲解速度。
11. As an 讲解人员, I want 人工选择对象时立即接管巡航, so that 镜头不会和我的操作竞争。
12. As an 讲解人员, I want 一键回到完整总览, so that 现场操作后能够迅速恢复展示。
13. As an 讲解人员, I want 选择走廊、观测场和专业专题, so that 我能围绕不同建设内容组织讲解。
14. As an 讲解人员, I want 按设施类型和设备类型开关图层, so that 大量监测点不会遮住地貌与设施。
15. As an 讲解人员, I want 缩远时看聚合数量、靠近时看设施和测点, so that 各种尺度下的画面都清楚。
16. As an 讲解人员, I want 通过对象列表或地图选择同一设施, so that 两种操作都能进入一致的详情。
17. As an 讲解人员, I want 搜索设施、桩号和测点名称, so that 我能快速回应现场关注的问题。
18. As an 讲解人员, I want 地图与精细模型之间连续切换, so that 观众知道模型对应的具体地理对象。
19. As an 讲解人员, I want 在模型中旋转、缩放和恢复推荐视角, so that 我能展示设施各个部位。
20. As an 讲解人员, I want 在路基和路面模型中展开结构层与埋设设备, so that 我能说明地下观测方式。
21. As an 讲解人员, I want 在桥梁中选中桥墩、桩基、孔位和深度测点, so that 我能讲清观测位置和构件关系。
22. As an 讲解人员, I want 在箱涵和圆管涵中展示围土与内部传感器, so that 我能解释涵洞观测内容。
23. As an 讲解人员, I want 在气象站模型中选中不同仪器, so that 我能展示环境观测的组成。
24. As an 讲解人员, I want 模型点位随模型剖切与构件移动保持正确挂载, so that 设备位置始终可信。
25. As an 展厅观众, I want 选中测点后立即看到正确的指标和单位, so that 我能理解正在展示的物理量。
26. As an 展厅观众, I want 数值和曲线持续产生新样本, so that 我能感受到数字观测的连续性。
27. As an 展厅观众, I want 温度、降雨、辐射、荷载和结构响应具有不同变化特征, so that 模拟观测具有合理的业务表现。
28. As an 讲解人员, I want 比较同一指标的多个测点, so that 我能展示空间位置不同所带来的观测差异。
29. As an 讲解人员, I want 切换实时窗口、历史时间范围和回放, so that 我能展示不同时间尺度的数据。
30. As an 讲解人员, I want 桥梁孔位和路基地温能显示随深度变化的剖面, so that 观测的三维分布能被看见。
31. As an 讲解人员, I want 放大曲线、查看光标值并恢复布局, so that 数据细节能在展厅里看清。
32. As an 展厅观众, I want 同一测点在地图、模型和曲线中的读数一致, so that 我能理解它们是在描述同一个对象。
33. As an 展厅观众, I want 看见设施数、测点数、设备数和模拟采集量, so that 我能理解数字化观测体系的规模。
34. As an 讲解人员, I want 通过完整的样例内容直接演示, so that 我无需准备数据、注册地图账号或配置后端。
35. As an 展厅维护人员, I want 使用静态部署包启动系统, so that 展厅播放不依赖业务服务。
36. As an 展厅维护人员, I want 在断开外网后仍可浏览所有交付场景, so that 网络波动不会中断参观。
37. As an 展厅维护人员, I want 资产加载失败时获得可恢复的反馈, so that 我能恢复画面而不进入死页。
38. As an 展厅维护人员, I want 系统连续巡航八小时仍保持稳定, so that 它适合展厅日常运行。
39. As an 展厅维护人员, I want 在不同 32:9 输出分辨率下保持同一构图, so that 我能适配实际显示设备。
40. As an 展厅维护人员, I want 图形质量可调整且文字保持清晰, so that 我能兼顾现场流畅度与画质。
41. As an 验收人员, I want 固定时间、种子和镜头下得到可重复的画面, so that 我能比较视觉修改与数据正确性。
42. As an 验收人员, I want 收到六场景截图和关键转场录像, so that 我能直接评审视觉与动效完成度。
43. As an 验收人员, I want 每一个可见控制都能完成对应操作, so that 交付是功能完整的前端工程。
44. As an 后续开发人员, I want 明确的对象契约、资产清单和模拟配置, so that 我能扩展监测内容而不破坏现有联动。

## Implementation Decisions

### 1. 工程定位与当前仓库

- 当前分支为 develop，受版本管理的内容只有代理协作与 Issue 约定；不存在已建立的业务词汇表、相关 ADR 或正式前端测试体系。
- 工作区另有未提交的三种布局视觉原型，采用 Vite、TypeScript、Three.js、程序化地形和静态 SVG 曲线。它只说明曾探索过视觉构图，没有正式地理数据、完整动态监测链路或验收基础。
- 另有未提交的综合工程基座草案，涵盖后端等更广范围；本规格不据此引入服务端。既有未提交内容属于用户工作，实施时不得覆盖、删除或当作已选定设计。
- 正式工程采用独立单页应用；可复用经过评估的通用视觉代码，但建立正式组件、资源生命周期、动态数据和验收边界。不得以改标题、去掉“原型”字样完成交付。
- 本规格为开发输入，本次规格发布不代表前端已经开发、构建或验收完成。

### 2. 技术组合与责任

| 能力 | 决策 | 责任边界 |
| --- | --- | --- |
| 应用 | React、TypeScript、Vite | 单一前端构建；依赖使用兼容稳定版本并锁定 |
| 地理 | CesiumJS | 真实地形、影像、路线、区域范围、地理模型与空间拾取 |
| 模型 | Three.js、React Three Fiber | 工程样例模型、构件选择、剖切、挂点和局部镜头 |
| 数据图表 | Apache ECharts | 时序、深度剖面、柱图、风向与统计；按需引入 |
| UI 动画 | Motion、CSS、SVG | 面板、标题、图例、控件反馈；不与相机控制争用状态 |
| 数据和状态 | 浏览器 Web Worker、轻量共享状态存储 | 统一模拟时钟、按需生成、查询、订阅和界面状态 |
| 静态资源 | GeoJSON、地形瓦片、影像瓦片、GLB、压缩纹理 | 地理与模型资产按 manifest 加载，全部主流程资源随交付包提供 |
| 验收工具 | Playwright、必要的契约测试工具 | 浏览器外部行为、视觉截图、动效和模拟一致性 |

Cesium 为地理主引擎，Three 为局部工程展示引擎。二者不叠放成两个持续高负载的全屏动态 Canvas。切换时预热目标场景，以短暂过渡交接；非活动场景停止渲染，超出缓存预算的模型释放 GPU 资源。地图内的简单 GLB 可直接由 Cesium 展示，无须切换引擎。

浏览器运行时不建立业务 HTTP API、WebSocket 服务、数据库、用户中心或服务端代理。读取静态文件、运行前端 Worker 和使用静态文件服务器均属于本工程范围。地理资产裁切、瓦片转换和模型压缩是构建准备工具，交付播放时不启动这些工具。

### 3. 品牌、色彩与独立视觉设计

品牌主体全称固定为“中交第一公路勘察设计研究院有限公司”，短称为“中交一公院”。主标题采用“青藏高原野外观测体系”，副标题“数字化监测展示”；如需兼顾旧称，“野外观测大数据管理系统”只作为配置化副标题备选。

已核验中交集团体系官方品牌页面对蓝色、蓝白对比和严谨线条的说明。本次未取得一公院独立完整 VI 手册，且其官网本次访问失败。因此以下 HEX 是依据中交品牌气质制定的屏幕设计色，不声称是官方 VI 标准数值。实现方直接采用该配色开始开发，不等待用户提供手册。

| 色彩用途 | 设计色 | 使用要求 |
| --- | --- | --- |
| 品牌主蓝 | #005BAC | 品牌区域、主操作、信息结构 |
| 深海背景 | #06192E | 全屏底色与边缘空间 |
| 面板背景 | #0C2946 | 保留层次，局部半透明，避免通屏重模糊 |
| 主要文字 | #F2F7FC | 标题、核心读数 |
| 次要文字 | #A8C0D8 | 单位、辅助说明；实际背景上校验对比度 |
| 交互亮蓝 | #38A8FF | 选中、聚焦、空间指引 |
| 青色辅色 | #4CD6DA | 次级路线、气象和流动细节 |
| 暖金辅色 | #D9B66F | 少量体系重点、主站和范围区分 |

- 企业标志必须使用可核验的官方原图并保留原始比例；无法取得时以完整企业名称与文字品牌完成页面，不临摹或生成看似官方的标志。
- 深蓝界面不把卫星影像整体染成蓝色。保留山体、积雪、水体与地貌的可辨色相，对地图局部做亮度与饱和度控制，为业务信息留出对比。
- 三类范围使用可区分色、边界线型和名称共同编码；图表系列颜色保持跨页面一致。
- 不复用旧图的机甲式边框、斜切页签、密集四宫格或满屏树状菜单。采用宽幅地理画面、少量信息面板、清晰字号层级和随对象展开的详情。
- UI 中“模拟观测数据”采用一个稳定、清晰的页脚说明；点选样例设施时显示“模拟布设”，样例模型显示“工程样例模型”。这些标识不反复覆盖每张卡片，也不把工程命名为 Demo。

### 4. 32:9 布局与可读性

- 逻辑设计尺寸为 3840×1080；主视觉验收尺寸 5760×1620，对应旧图比例。另检查 3840×1080、5120×1440、7680×2160。1920×540 提供等比评审预览，不作为展厅阅读距离基准。
- 外层按 32:9 布局，非 32:9 视口等比留边，不拉伸地形、模型、字体或圆形控件。使用布局计算适配，不能只缩放页面却不更新 Canvas 尺寸和拾取坐标。
- 主场景铺满背景；总览的左右信息区各占约 15%–18%，中央无面板遮挡宽度不低于 64%。模型专题可将右侧观测区扩大到约 25%，中央有效模型区仍不低于 55%。
- 逻辑尺寸下主标题 44–56 px、区标题 26–32 px、正文和控制 20–24 px、图表刻度和单位不少于 16 px。微型英文装饰不得承载必要信息。
- 顶部品牌与导航高度约 90 px，底部控制与状态约 56 px，左右安全边距至少 48 px。关键标识与选中标签不得被屏边裁切。
- 顶层入口固定为总览、路基、路面、桥梁、涵洞、气象。总览用“四类专业”说明路基路面属于一个专业族；专题界面分成两个入口满足实际指标差异。
- 面板默认呈现最重要的 2–3 个图表；其他指标通过指标选择和图表放大访问。所有规定指标均可操作访问，不能以“画面放不下”为由删减。

### 5. 六个场景的完成定义

| 场景 | 中央舞台 | 左侧内容 | 右侧内容 | 必须可操作 |
| --- | --- | --- | --- | --- |
| 总览 | 高原卫星三维全貌、一站两廊三场、设施分布 | 体系组成、走廊与观测场入口 | 设施/测点/设备规模、模拟采集动态、专业构成 | 走廊聚焦、范围选择、专题、图层、巡航 |
| 路基 | 地理近景或含冻结层和埋设传感器的路基剖面 | 路段/断面/孔位选择、构件与测点清单 | 地温、含水量、横向位移、分层变形；可选通风板风速 | 剖切、埋深选择、孔位剖面、测点联动 |
| 路面 | 路面层状结构与轴载观测位置 | 断面、结构层、设备 | 轴载、结构层温湿度、竖向压应变、累计变形；其他规定指标可切换 | 结构层展开、车辆经过事件、响应曲线 |
| 桥梁 | 桥面、桥墩、桩基础及孔位的三维模型 | 桥梁/墩/桩/孔位层级 | 桩身温度与桩基应变的时序和深度剖面；桩侧温度、墩位移可选 | 地下结构揭示、点位/孔位模式、构件高亮 |
| 涵洞 | 箱涵或圆管涵及围土剖面 | 涵洞、构件、设备类型 | 管周土温、含水率、土压力、应变、变形沉降 | 模型类型切换、围土剖切、内部挂点 |
| 气象 | 地理环境与气象站设备模型 | 气象断面和仪器选择 | 温湿度、风、气压、雨量和辐射；环境读数矩阵 | 仪器点选、风向联动、时间范围、图表放大 |

主站提供站点说明、空间聚焦和样例站区模型，作为总览内的详情场景，不另增管理页面。所有场景含对象名称、所在走廊、专业、指标单位、模拟时间与返回入口。无选中设施时采用该专业预设代表设施，并明确显示选中对象，禁止图表处于无归属状态。

### 6. 一站、两廊、三场的样例编排

- 一站：沿用旧图的“花石峡野外观测站”作为展示名称。定位到公开花石峡地理位置附近的样例站区，属性明确为“站区位置为模拟布设”；不能把城镇坐标当成真实站房测量坐标。
- 两廊：青藏走廊对应格尔木—那曲国道；青康走廊对应共和—玉树国道。中文全称与起终点为固定展示语义。线路根据公开道路数据整理为连续路线，不使用两点直线、随意贝塞尔曲线或程序化山形代替地理道路。
- 三场：气候环境观测场、结构材料观测场、实体工程观测场。它们是三种观测类别与范围，不是三种监测专业，不要求互斥，也不强制一个类别只对应一个地点。
- 默认每条走廊配置三个范围实例，三种类别各一处，共六个可点选范围实例；总览标题仍为“三场”，范围详情分别显示类别与实例名称。这六处边界为工程提供的模拟 Polygon/MultiPolygon，不声称是正式建设边界。
- 观测场允许跨越多处设施。设施的 fieldIds 是多值关系；场范围统计用对象 ID 去重，避免重叠区域重复计数。
- 默认目录含 80 处样例设施，每廊 40 处：路基 12、路面 12、桥梁 6、涵洞 6、气象 4。主站单列，不挤入这 80 处设施的分类计数。
- 配置至少 2,500 个测点、600 台设备和 4,000 条有效观测序列，以真实触发聚合、过滤和性能需求。具体总数由生成后的目录计算；界面不能另写不一致的固定数字。
- 所有设施有可用的地理位置、专业归属、至少一个指标、可访问模型和有效挂点；所有实体名称使用“样例”属性说明。相同类型的不同设施可共享模型模板，但尺寸、测点分布及标注由各自配置驱动。

| 资产 | 默认来源与处理方式 | 覆盖及质量要求 |
| --- | --- | --- |
| 区域卫星底图 | Sentinel-2 L2A 120m Mosaic，选择低云、可辨地貌的固定时段，裁切并生成静态影像层 | 两廊外包范围及上下文区域，建议初始范围 88°–104°E、29°–39°N；最终相机限制在完整资产覆盖内 |

| 局部设施 | 自制、程序化生成或可再分发的 GLB 工程样例模型 | 覆盖全部设施类别、可选构件、真实三维厚度和材质 |

公开目录已确认存在免 AWS 账号访问的相关 DEM、Sentinel-2 COG 和 120m Mosaic。实施阶段仍须检查选定瓦片在目标范围内的有效覆盖、日期、云量、拼接和条款；本规格没有宣称已经下载或逐瓦片核验这些资产。

具体约束：

1. 地理数据资产带有 source、license、attribution、acquiredAt、extent、resolution、CRS、verticalDatum、version、checksum；影像记录成像期而非显示为实时卫星画面。
2. 标准化经纬度使用明确的 WGS84 地理坐标；地形和模型的高度基准必须明确。Copernicus DEM 是表面高程数据，不能凭名称当作裸地测量。高程转换和地表贴合在资产准备阶段明确处理，避免设备埋入地表或悬浮。
3. 站点、范围和样例设施共享同一地理坐标框架；生成设施位置时绑定所属线路或站区，不能随机散布到走廊之外。
4. 地图缩放有资产覆盖和分辨率约束。到达卫星影像有效细节极限后，引导进入工程模型；继续放大不能用平滑插值冒充现场高清。
5. 无项目航测成果时，不要求伪造摄影测量实景。交付名称分别为“卫星三维地理”“工程样例模型”；所用数据有来源即可构成完整前端交付。
6. 所有必需资源在发布前随静态资产包提供，不能留下一次性下载链接、运行时外部令牌、待补模型或空白瓦片。完整包复制到任意静态服务器后，屏蔽外网仍可完成全部巡航。
7. 保留依法及授权要求的来源标注。不得通过擅自缓存受限商业瓦片满足离线要求。无需付费地图账号是默认验收条件。
8. 原始大型测绘文件不进入浏览器。交付裁切后的瓦片、LOD 模型和纹理；建议运行资产控制在 2 GiB 内，超过时记录资产组成和真实加载证据。

### 8. 模型资产与挂点

至少制作八种完成材质与构件分组的模型模板：野外站区、通风/热棒路基、块石路基、层状路面、含桩基础桥梁、箱涵、圆管涵、综合气象站。路基专题可由两个模板配置出其他样例布置。站区有可辨主体建筑和观测设备；不能用单一无材质立方体充当完成模型。

- 模型使用米制单位、明确局部坐标轴和原点；每个可选构件有稳定 semanticId，每个传感器有独立锚点，模型版本变化需重新验证锚点。
- 支持外观、结构剖视、测点布设三种表现。剖视用裁切面或层级展开，显示切面与结构层；透明材质注意前后遮挡，避免所有表面叠成亮团。
- 点位挂载包含 facilityId、componentId、pointId、modelAssetVersion、localPosition、可选 localNormal 和模型到地理空间变换。屏幕标签由三维投影计算，不保存百分比屏幕位置。
- 模型展开时，锚点随所属构件变换；地图中保留设施的原始地理定位。剖面中的示意层距不能回写成地图坐标。
- 普通点遮挡时隐藏或降权，选中点可使用带引线的透视标记并注明位于内部。不能把被遮挡点错误绘制到外表面。
- 测点位置可拾取，有足够点击区域；光效变化不得改变实际点击范围。
- 所有模板带近景推荐镜头、整体镜头、剖视镜头和局部检查镜头。各场景不同的模型组合、光照与构图要有明显差异。
- 使用 PBR 材质、适度阴影、环境光和局部描边；Bloom 只用于选中构件及少量光效，不造成文字和模型边缘过曝。
- 贴图优先压缩格式；网格采用 LOD、实例化和合并策略。离开模型后必须释放不再使用的几何、材质、纹理和标签监听器。

### 10. 动态模拟运行时

模拟运行时是正式功能模块，在 Web Worker 内运行，对外提供读取目录、空间筛选、读取快照、读取时间序列、读取深度剖面、订阅变更、控制模拟时间等少量能力。界面、模型和地图不各自生成随机数据。

**确定性和时钟：**

- 默认 seed 为 20260925，模型版本为 sim-v1，模拟起始时刻为北京时间 2026-06-21 10:00:00。打开后以 1 倍速持续推进；显示“模拟时间”。如展示现实时间，单独标为展厅时间。
- 样本由 seed、seriesId、物理模型版本和采样时间确定。历史、实时、回放与页面刷新后的同一时间查询应返回相同结果，不使用依赖调用顺序的随机序列。
- 观测时钟与讲解时钟独立。暂停巡航只停止镜头和讲解序列，数据继续采样；暂停观测回放才冻结观测时间。冻结后所有读数、曲线和累计量保持一致。
- 提供 1×、10×、60× 回放，支持恢复当前模拟时刻和一键重置演示。拖动时间轴时先定位统一时间，再让所有视图使用同一 revision 渲染。
- 可配置最近 15 分钟、1 小时、24 小时、7 天及 30 天内自定义范围。超出可查询范围明确限制；不出现控件可选但曲线无意义的未来区间。

**生成规则：**

| 数据族 | 必需动态特征 | 样例生成包络 |
| --- | --- | --- |
| 空气/表层温度 | 昼夜周期、走廊/海拔差异、平滑扰动 | 气温约 -20～25 ℃，结构表层可采用 -25～45 ℃ |
| 深部温度 | 振幅随深度衰减、相位滞后、不同孔位有相关差异 | 深部示例约 -8～8 ℃；不是一组简单相移的同形线 |
| 含水率/湿度 | 有边界、与降雨及温度存在连续关联 | 体积含水率约 5%～55%，相对湿度约 15%～95% |
| 风 | 连续变化、阵风事件、风向跨 0° 正确插值 | 风速约 0～20 m/s，风向 0°～360° |
| 气压 | 随样例海拔设定基线、平滑小幅变化 | 高原样例约 50～80 kPa |
| 降雨 | 连续的降雨过程、非负分时量、日累计单调增加 | 日界线统一按北京时间重置，不能每帧随机变小 |
| 辐射 | 日夜变化，短波和紫外夜间接近零，净辐射允许为负 | 总短波 0～1,200 W/m²；紫外 0～60 W/m²；净辐射 -150～800 W/m² |
| 轴载/应变 | 共同车辆事件驱动的脉冲、构件传播与衰减 | 轴载样例 20～160 kN，应变按构件配置约 -300～300 με |
| 位移/沉降 | 缓慢趋势与温度相关项，保留有符号读数 | 位移约 -10～20 mm，累计变形按固定基准计算 |
| 土压力/热流 | 有结构基线与时间响应，不套用温度曲线 | 土压力约 20～250 kPa，热流按结构约 -120～200 W/m² |

这些包络用于避免负雨量、2000 ℃ 土温、错位单位等明显错误；不构成物理仿真或科研模型。各设施可使用不同参数，采用平滑噪声及共同事件，确保看起来有连续性而非所有图同步正弦摆动。

**采样、查询与负载：**

- 环境类默认每 5 个模拟秒采样，慢变结构类每 10 个模拟秒；车辆事件窗口内荷载/应变样例按 10 Hz 生成，非事件段可按低频显示。元数据必须标明实际采样周期。
- 视图快照最多每秒合并推送一次，活动曲线每秒更新 1–2 次；动态数字平滑过渡不能修改实际样本值。时序 tooltip 显示准确采样值与时间。
- 不为全部序列长期保存逐秒数组。按查询窗口确定性生成，订阅当前需要的序列，用有上限的环形缓冲与缓存承载当前数据。
- 一般图表每序列最多输出 1,200 个可绘制点，放大图最多 2,400 个；采用保留局部极值的聚合，不能把车辆尖峰直接平均掉。历史聚合桶与实时桶定义一致。
- 新增样本数和累计样本数根据采样周期、事件与时间区间计算，使用 64 位安全表示或 BigInt 处理长期计数；页面只格式化，不另写增长动画值。
- 当前目录是稳定建设规模，设施数/设备数不随每次刷新抖动；数据样本量、当前值和时间曲线持续变化。
- 默认全部设备正常产生模拟数据。缺测/断流只用于维护与测试状态，显示“暂无数据/数据暂不可用”，不扩展为告警模块。

### 12. 地图、图层和模型交互

- 固定图层顺序：地理底座 → 两廊 → 三场范围 → 设施 → 测点 → 设备标注 → 选中态。图层透明度、开关、图例和数量可查。
- 常规总览显示全部体系。精细图层随缩放展开；主站、当前走廊名称、三场图例和选中对象具有最高标注优先级。
- 远景以设施聚合为主，聚合显示当前过滤条件下的数量；点击聚合逐级展开。选中点不能被合并后丢失，其上下文保持可见。
- 设施与设备类型使用颜色加图形编码，不只依赖颜色。模型中默认活动标签不超过 30 个，可用列表搜索访问所有测点。
- 搜索、图层筛选、对象树和地图拾取作用于同一目录；统计严格对应当前范围和去重口径。
- 地图进入模型前记录地理相机、对象和过滤状态；模型载入达到可展示状态后再转场。退出时恢复原位置、层级和选择。
- 模型加载失败维持已可用地理场景和对象详情，提供重试；正常发布包的所有模型都必须能够成功进入，失败状态不能替代完成交付。
- 切换设施时取消旧查询及相机任务；快速连点只执行最新意图，不叠加多个飞行。Esc 先关闭弹层，再退回上一层；Home 返回总览。
- 图表与模型双向联动：选择曲线系列可定位测点，选择孔位高亮对应深度点；保持同步游标时各图使用同一观测时间。

### 13. 图表与监测展示细节

- 时序图有真实动态 x 轴、明确 y 轴和单位、最新样本时间、系列图例、光标读数。图表切换不使用写死的 SVG 折线或重放短循环冒充新数据。
- 同一指标可比较 1–6 条序列；默认 3 条，六条使用颜色与线型共同区分。单位不同的物理量默认分图，温湿度等明确双轴图可例外。
- 孔位剖面横轴为物理量、纵轴为深度 m，深度向下增加。剖面是同一时刻不同深度的数据，不能把时间曲线横放冒充剖面。
- 雨量按时间桶求和，累计量按日界线积分；风向使用角度数据与方位映射，不能对 359° 和 1° 算术平均成 180°。
- 放大图表保留选中对象、系列、时间范围和模拟时间；关闭后恢复前一布局。历史查询期间实时模拟继续运行但不覆盖用户历史窗口，点击“跟随当前”才回到滚动视图。
- 缺值绘制断点并标明无样本，不补零；生成和聚合必须保留数据质量标识。
- 模拟车辆可以在路面/桥梁样例模型上短暂经过，与同一事件的轴载和应变峰值同步。车辆移动是局部讲解效果，不作为道路交通事实。

### 14. 科技动效与演示编排

动效由一个演示控制器协调。场景、相机、图层和信息面板共享带取消能力的阶段切换，避免分别计时导致竞态。进入交付页面即显示完整可用总览，不强制播放片头。

| 动效 | 设计行为 | 建议时长/约束 |
| --- | --- | --- |
| 按钮与图例反馈 | 光边、位移或选中标识即时响应 | 120–220 ms；不缩放点击区域 |
| 面板切换 | 短距离位移、透明度和标题顺序显现 | 240–450 ms；正文到位后静止 |
| 走廊聚焦 | 相机先收敛到范围，再沿线路进入；线路描绘一次 | 1.8–3.2 s，飞行可取消 |
| 场范围展开 | 地表边界分段显现、范围轻亮后保持 | 0.8–1.4 s，实际边界不移动 |
| 设施聚焦 | 目标高亮、相机转向、名称保持连续 | 1.2–2.2 s，避免穿地和大幅翻滚 |
| 地图到模型 | 目标对象位置与名称连续，背景退场，模型已就绪后显现 | 0.8–1.5 s；允许短暂双场景过渡 |
| 模型剖视 | 结构层有序展开，设备挂点随构件移动 | 0.9–1.6 s；可一键复原 |
| 点位选择 | 稳定光环、局部引线、对应曲线进入 | 200–450 ms；保留选择上下文 |
| 数据更新 | 曲线滚动、数值轻微过渡、采集状态柔和变化 | 不制造全屏闪烁，不伪造中间采样值 |

- 科技感重点来自有深度的地形、电影式但可控的镜头、工程结构揭示、统一材质与精确联动。可加入局部扫描和细线粒子，但不得盖住地理信息或被解释成真实数据传输。
- 两廊以稳定高亮线常显。持续奔跑的路线光包不是默认背景；选中或讲解时可一次性描边，保持固定设施清晰。
- 暂停巡航后，镜头停止，模型选择继续可用；鼠标操作立即取消自动飞行。自动恢复只在启用待机巡航时发生，默认人工讲解不擅自夺回控制。
- 提供“标准动效”和“低动效”质量选项。正常模式必须有完整动效，低动效仅用于性能或现场需要，不能替代视觉验收。
- 场景暗转不得以全黑屏遮盖加载；预加载期间保持上一个完整画面，目标就绪后交接。

默认巡航约 5 分钟，编排为：总览 35 秒、主站与三场 25 秒、两廊各 25 秒、路基 35 秒、路面 35 秒、桥梁 40 秒、涵洞 35 秒、气象 35 秒、返回全貌约 10 秒。时长为含转场的可配置建议，循环衔接不重复初始化应用。每段有预设对象、相机、图层、模型状态、指标和停留时间，可上一段/下一段/暂停/继续。

### 15. 运行、缓存与静态部署

- 开发提供单一安装、启动、构建、预览和验证入口，文档使用实际存在的命令；锁文件提交并可重复安装。静态产物支持部署在域名子路径下，刷新深链接能返回正确场景。
- 默认使用本地静态资源，不依赖外部 CDN 字体、运行时模型下载或地图账号。随包包含中文字体许可和所用字形、解码器、Cesium Worker 等必需内容。
- 启动先读取 manifest 与目录，加载总览必需低层级影像和地形，再预加载巡航下一段的资源。资源失败能够定位到资产 ID 并重试。
- IndexedDB 可存用户展示偏好与有界缓存，但不是启动必需数据源；首次启动与清空浏览器存储后均可运行。磁盘不足时回退到内存并保持主流程。
- 运行时异常、WebGL 上下文丢失和过期请求有统一恢复策略；恢复后对象选择和模拟时间不无故跳变。基础设施事实与品牌内容不存储在临时浏览器会话中。
- 应用内提供全屏、总览复位、质量设置和资源来源入口；维护信息放到可收起的维护面板，不占主舞台。第一版不需要远程手机控制或多端同步。

### 16. 性能与资产预算

性能以记录明确的参考主机实测：建议桌面级独显、至少 8 GB 显存、16 GB 内存、现代 Chromium 浏览器，主验收视口 5760×1620。此配置是待验证基线，不是未经测量的性能保证。

- UI 和文字按输出分辨率清晰渲染；三维渲染比例可自适应 0.67–1.0，输出宽度较大时不再盲乘高 DPR。7680×2160 必须布局正确，帧率结论需在对应设备独立记录。
- 主机基线下静态场景稳态目标中位帧率不低于 30 FPS，动态镜头的 P95 帧耗时不超过 50 ms；稳定选择反馈在 100 ms 内可见。UI 动画尽量接近屏幕刷新率。
- 本地静态服务冷启动总览目标 8 秒内达到可讲解状态，预加载完成后的模型切换目标 2 秒内完成。记录资源体积、首次/缓存状态，不混用结果。
- 正常可见标签总量、图表序列、解码并发和模型缓存均有上限；不能为数千测点创建数千 DOM 标签。
- 全局仅一个活动三维主循环，过渡期可短暂重叠。模拟更新通过批处理传递，React 不每帧重建几何或整棵页面。
- 连续八小时自动巡航及 100 次地图/模型切换无崩溃、无法恢复黑屏、失效交互或持续增长的缓存。预热后相同巡航节点的内存不持续单调增长；可观测 JS 堆增长控制在 20% 内并结合 GPU 资源数量及缓存上限评审。
- 不为追求帧率自动隐藏一站两廊三场、当前选中对象、必要单位或所有动效。降级顺序是装饰粒子、阴影精度、后处理、三维分辨率，文字与业务可见性最后保障。

## Testing Decisions

### 1. 验收边界

用户已选择视觉与动效优先。主要测试边界是浏览器中的完整大屏，通过公开交互观察最终画面、状态和数据。尽量用同一条“总览 → 走廊 → 范围 → 设施 → 模型 → 测点 → 曲线 → 返回”链路覆盖模块组合，不为每个内部组件另造重复测试层。

仅给动态模拟运行时增加必要的外部契约测试，以固定种子、时刻、序列 ID 和查询窗口验证其输出。这一补充用于浏览器难以穷举的时间一致性、聚合和物理量约束；不测试内部私有函数调用顺序、组件树或框架实现细节。

当前仓库没有可沿用的正式测试样例。已有视觉原型的构建命令和静态曲线不能作为功能测试先例。实施应建立最小浏览器测试入口、确定性截图条件和模拟运行时契约测试；文档本次只进行规格一致性检查，不运行不存在的产品测试。

### 2. 视觉与动效为首要交付证据

- 六个场景在 5760×1620 原尺寸各至少一张完整截图；追加总览、桥梁剖视与气象在 3840×1080 和 7680×2160 的布局截图。不能只提交缩小浏览器窗口的截图。
- 每个专题至少包含地理视图与模型视图的可见证据；桥梁与路基有孔位/深度剖面证据，图表放大有独立截图。
- 交付完整巡航录屏，以及走廊飞行、场范围展开、地图/模型往返、剖切挂点、车辆/曲线联动、快速切换打断这六类短录屏。至少 30 FPS 捕获，注明实际捕获尺寸，不能用静态截图证明动效通过。
- 截图使用固定 seed、模拟时刻、资源就绪状态、相机和图层；视觉比较屏蔽现实时间等无关变化。截图稳定测试之外仍须独立录制正在运行的动画。
- 用对比度、标签碰撞、屏边裁切、地形/模型细节、镜头连续性、图表单位和品牌可辨识度组成评审表，不把“所有 DOM 都存在”作为视觉完成证明。

视觉评分按 100 分：32:9 构图与可读性 20、品牌与色彩 15、地理地貌与模型质量 20、镜头与转场 20、操作反馈及数据动感 15、跨场景统一与完成度 10。建议通过门槛总分至少 85，且每项不少于该项满分的 70%。评分结合截图和录像人工审阅；下述硬性失败项不得被总分抵消。

硬性失败：任何必需场景空白；黑屏遮盖转场；模板复用后仍只有一套曲线；旧图直接充当新界面；场范围被画成三个点；路线不遵循所用公开道路；用平面图假装可交互模型；全部数据静止；出现无效按钮；离线缺主资产；展示文字或单位被裁切。

| 编号 | 操作或条件 | 通过标准 |

| AC-13 | 暂停巡航与暂停回放分别操作 | 巡航暂停不冻结采样，回放暂停冻结全部观测视图，恢复后连续 |
| AC-14 | 设置种子与时间并重复查询 | 快照、历史、实时交界处一致；采样时间不重复、不倒退 |
| AC-15 | 历史范围、回放速度、跟随当前 | 查询范围生效，倍速统一作用于观测数据，历史窗口不被实时刷新夺回 |
| AC-16 | 路基和桥梁孔位模式 | 深度轴向下，温度/应变单位正确，同一时刻多个深度有对应挂点 |
| AC-17 | 检查降雨、辐射、风向和过车事件 | 日累计与分时和一致，夜间短波近零，风向正确过零，轴载与响应同事件同步 |

| AC-21 | 断外网且清空浏览器缓存后从完整静态包启动 | 全部地理、模型、曲线、字体、动效可用；无需曾经在线运行 |
| AC-22 | 注入单个模型/影像加载失败 | 保留可用画面并可恢复；恢复后继续原操作，正常包无缺失资产 |
| AC-23 | 32:9 多分辨率切换 | 构图和交互拾取正确，字体清晰，无页面滚动条、遮挡及伸缩变形 |
| AC-24 | 主设备帧率、启动与切换测量 | 达到性能节规定门槛，报告硬件/浏览器/尺寸/渲染比例与资产状态 |
| AC-25 | 连续八小时与 100 次切换 | 无崩溃或黑屏，交互继续有效，无无界内存/订阅/纹理增长 |
| AC-26 | 对照指标目录逐项打开 | 监测表全部指标可达，元数据正确；科研/告警/处置入口不存在 |
| AC-27 | 检查最终文字、品牌与来源 | 无占位字、待接入按钮或伪官方标志；模拟数据标识和必要来源署名完整 |
| AC-28 | 审阅六场景截图与动效视频 | 视觉评分达到门槛，硬性失败项为零；不能用 build 通过代替此项 |

## Out of Scope

- 业务后端、数据库、身份认证、设备真实连接、数据采集平台和数据中台。
- 真实单位建设规模、真实传感器清单、实际监测数值和测绘级精度承诺。
- 告警、应急处置、风险评价、预测、科研成果与科研分析。
