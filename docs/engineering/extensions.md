# 扩展工程基座

工作区、模块依赖、Compose、环境配置分别是所属信息的权威来源。不要增加第二份描述整个仓库的通用注册表。先明确实际需求和调用边界，再添加模块；没有真实复用时不要建立空共享库。

## 新增 Go 服务或共享模块

1. 在 `services/<name>` 建立独立 Go Module，路径使用 `github.com/WenshuaiDev/Omega/...`，添加根 `go.work` 的真实仓库内成员。依赖由该模块自己声明；仓库内相对替换只能指向仓库内实际目录。服务之间不能导入对方内部实现。
2. 服务提供固定工具链、多阶段 Dockerfile 的 `development` 和 `production` 目标。正式镜像非 root，写入统一版本/提交标签，声明健康接口和有界关闭行为。实际共享模块不必单独发布镜像。
3. 接入基础/开发/正式 Compose，以及 test/prod 显式差异；声明网络、输入、Secret、持久化、权限、资源、日志轮转和健康。只允许 edge 发布入口；迁移由服务所属 CLI 显式执行，不把 omega 扩展成跨服务数据库中央入口。
4. 接入 dev 的镜像、依赖准备、显式迁移和 smoke 顺序，接入 release 候选镜像清单/离线材料/兼容声明。正式构建必须复制真实全部依赖，不能依赖开发者绝对路径。
5. 增加可观察命令/HTTP/持久化行为测试。统一检查自动发现 `go.work` 成员，并拒绝仓库中遗漏的 Go Module；每个服务 Dockerfile 自动参加正式构建。运行 `make check` 及实际启动/失败验收，记录新入口。

## 新增前端应用或共享包

1. 放在 `apps/<name>` 或真实复用的 `packages/<name>`，通过根 Yarn workspaces 发现；独立包名，内部依赖用 `workspace:*`。只维护根 `yarn.lock`，使用固定版本和 node-modules；不导入其他 app 的源码。
2. 每个成员提供 `typecheck`、`lint`、`test`；app 还必须提供 `dev` 和 `build`。源码共享包可以不输出独立构建产物。统一入口直接遍历所有实际成员，不能靠 `foreach` 静默跳过缺少的检查。
3. 为 app 固定 base、深层路由和 HMR 路径，增加独立 runtime JSON 严格校验及 edge 精确返回规则。错误配置必须显示失败，不回退默认 API。配置 no-store，HTML 及时更新，哈希资源长期缓存，缺失资源 404。
4. 更新 `apps/Dockerfile` 的 APP 构建支持、独立静态镜像、Compose 开发服务器及依赖安装挂载。嵌套 node_modules 和安装状态都要有可写位置；只允许一个安装写入入口。
5. 接入完整输入校验、edge DNS 发现/HMR、dev smoke、release 镜像列表和离线材料。统一检查会发现新 app 并构建，但不能自动替代这些显式接入。新增真实浏览器及失败场景后再次执行 OMEGA 验收。

## 新增基础组件

明确其权限、数据、网络、健康检查、超时、生命周期、Secret 需要和失败保留行为。固定经过验证的版本，接入 Compose、镜像包、导入内容身份校验和正式模型检查；平台必须符合 Linux amd64。不要为了接入组件给应用 Docker socket、宿主网络或管理权限。数据库大版本升级不属于普通应用发布。

## 维护依赖和证据

依赖更新是单独的显式维护操作；普通启动和检查不能运行 go mod tidy、Yarn 更新或其他改写锁文件的操作。修改权威版本后更新匹配镜像工具链并执行兼容检查，保留 immutable 失败负例。依赖和镜像实际测试通过前，不把候选版本写成验证结果。

`make check` 证明当前源码的质量、真实测试、模型策略和正式构建；完整浏览器、离线部署、原生平台和生产交付各有独立证据。存在新增组件或未执行平台时保留相应未完成项，不能通过减少报表范围宣称全部验收通过。
